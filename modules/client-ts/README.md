# @skkil/store-client

The TypeScript sync driver for a `store-core` handle. The browser uses the core
compiled to WASM in a Web Worker, and React Native uses the uniffi module. The
driver owns the networking: it pushes to the product server, pulls from the
store service, listens for pokes, and gives each response back to the core.

## Commands

```bash
pnpm install --frozen-lockfile
pnpm generate          # regenerate src/gen from ../protocol/proto (buf + protoc-gen-es)
pnpm check:generated   # fail if src/gen is stale
pnpm lint
pnpm typecheck
pnpm test              # Vitest: unit tests plus a connect-node integration test
pnpm build             # dist/ (ESM + .d.ts)
pnpm format            # Prettier
```

## Usage

```ts
import { createSyncDriver } from "@skkil/store-client";

const driver = createSyncDriver({
  core, // CoreHandle
  storeUrl: "https://store.skkil.org",
  pushUrl: "https://time.skkil.org/api",
  getSyncToken: () => api.syncToken(), // string or { token, expiresAt }
  getPushHeaders: async () => ({ Authorization: `Bearer ${await auth.accessToken()}` }),
  onChange: (tables) => queryClient.invalidateQueries({ predicate: touches(tables) }),
  onStatus: ({ online, pending, lastSyncedAt, issues }) => setSyncState(...),
});

await driver.syncNow();
await driver.stop();
```

In React Native, pass `fetch` from `expo/fetch`. The built-in RN fetch cannot
stream, and the Pokes stream needs that:

```ts
import { fetch } from "expo/fetch";
createSyncDriver({ ...options, fetch });
```

### The core handle

```ts
interface CoreHandle {
  pushRequest(limit: number): Uint8Array | null; // binary PushRequest, null when nothing waits
  applyPushResponse(bytes: Uint8Array): void;
  pullRequest(limit: number): Uint8Array; // binary PullRequest
  applyPullResponse(bytes: Uint8Array): { changedTables: string[]; more: boolean; reset: boolean };
  status(): { clientId: string; pending: number; issues: number; cursorVersion: bigint };
}
```

### Behaviour

- **Cycle.** Each cycle pushes batches until `pushRequest` returns null (or
  repeats the same batch), then pulls pages while `more` or `reset` is set.
  After a Reset, the driver runs one more cycle to re-push pending mutations.
  Cycles never overlap: requests made during a cycle coalesce into one more.
- **When it syncs.** On start, after the Pokes stream (re)connects, on a poke
  whose version is ahead of `cursorVersion`, on `syncNow()`, every
  `pollIntervalMs` (60 s), and, where `window` exists, on `online` and when
  the document becomes visible.
- **Failures.** A failed cycle is retried with full-jitter exponential backoff
  (1 s base, 60 s cap). Mutations stay in the core until a pull acknowledges
  them, so nothing is dropped. The Pokes stream reconnects with its own
  backoff, and the `online` event cuts the wait short.
- **Tokens.** The sync token is fetched lazily and replaced
  `tokenRefreshMarginMs` (60 s) before it expires, using `expiresAt` or the
  JWT `exp` claim. After a 401 it is dropped and the pull retried once.
  `getPushHeaders` runs before every push.
- **One leader.** By default only one tab or worker per origin syncs. It holds
  the Web Lock `skkil-store-sync` until `stop()`. Without `navigator.locks`
  (React Native, Node), the driver leads at once. Pass `lock` to override.
- **DOM-free.** `window`, `document` and `navigator` are only used after
  feature detection.

## Layout

```
src/
  index.ts                 public API
  driver/
    sync-driver.ts         createSyncDriver: wiring, cycle (push → pull), triggers, status
    sync-loop.ts           single-flight cycle runner with retry backoff
    poke-listener.ts       Pokes stream with reconnect backoff
    token-cache.ts         sync token cache and refresh
    backoff.ts             full-jitter exponential backoff
    core-handle.ts         CoreHandle, SyncStatus, PullApplied
    driver-status.ts       DriverStatus reported to onStatus
    sleep.ts, aborted.ts   abort-aware helpers
  transport/
    store-transport.ts     Connect client for StoreService (Pull, Pokes) with the sync token
    push-transport.ts      Connect client for PushService with product headers
    errors.ts              401 detection
  lock/
    leader-lock.ts         LeaderLock interface
    web-lock.ts            Web Locks implementation
    noop-lock.ts           single-context fallback
    default-lock.ts        picks one by feature detection
  gen/                     generated by buf from ../protocol/proto (committed)
test/
  driver/, lock/           unit tests against FakeCore and FakeTransports
  integration/             driver ↔ in-process connect-node StoreService and PushService
  support/                 fakes and the test harness
```
